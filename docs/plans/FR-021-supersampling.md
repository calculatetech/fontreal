## Research and selected path


Actual retained captures show a source difference: Arial10pt glyph O has a native-normal bitmap width of10 pixels and native-MONO width8. At11pt the widths are11 and10. Its outline points move horizontally by up to64/64 and30/64 pixels respectively. Noto Sans10/11pt O and parentheses have identical native-normal and native-MONO outlines. This supports investigating targeting; it does not establish that every optical defect comes from hinting.

FreeType separates hint targets from bitmap render modes. `FT_LOAD_TARGET_MONO` can therefore precede grayscale rendering. `FT_LOAD_NO_HINTING` supplies the unhinted control. See [glyph loading and rendering](https://freetype.org/freetype2/docs/reference/ft2-glyph_retrieval.html#ft_load_target_xxx) and [FreeType's hinting discussion](https://freetype.org/freetype2/docs/hinting/text-rendering-general.html). The latter is historical background; actual captured flags and effective properties decide this study. Existing off captures at4× are not valid unhinted1× controls.

O uses one component-wide phase, while L uses permitted per-pixel maxima from the same fixed native outline. U retains L cores and changes only fringe amplitude. The new trial reuses O's squared-energy contrast score over small local neighborhoods. It changes reference selection rather than blurring coverage. A midpoint of O/L is cheaper, but only attenuates their difference and cannot test phase coherence. Whole-mask blur changes the base and support. Global phase optimization or contour tracking is deferred until this reversible test gives evidence. This is a small extension of the existing scoring mechanism, not a production architecture commitment; the NeuroArxiv costly-effort gate does not qualify. No novelty claim is made.

Consider exactly the phases allowed by the existing E axis at i: horizontal shifts for axis x, vertical shifts for axis y, and all25 for xy.
