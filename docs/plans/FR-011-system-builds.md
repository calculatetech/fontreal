# On-demand builds for a KDE system

## Outcome and authority


Build and apply Fontreal with the running system's package manager. Debian 13 amd64 with Qt 6.8.2 and Ubuntu 26.04 amd64 with Qt 6.10.2 are the initial supported systems. Detect the installed Qt source revisions. Preserve distro package names, file ownership, existing fonts, explicit rendering controls, and ordinary security updates. Build matching QtBase and Qt Declarative packages, corresponding modified source, and a separate activation package that starts disabled.

The user requests Debian 13 and on-demand builds before hosted distribution. Source: the current conversation and [deployment decision](../research/distribution.md). This explicitly supersedes only the earlier Ubuntu-only initial target and hosted-distribution-first ordering in that decision. Scope: unfinished FR-011/FR-012 delivery work. The accepted renderer, opaque-target limit, private repository, package ownership, pre-install validation, and recovery requirements remain. The [FR-013 specification](FR-013-quick-linear.md) and [FR-014 specification](FR-014-a8-profile-scope.md) supply preserved rendering behavior. No prior completed checkpoint is rewritten.

## Product boundary and supported model


One local user runs one build or package transaction at a time. The system uses the official repositories for its release, a working local Docker engine, normal local storage, and native amd64 packages. Docker isolates dependency installation and compilation from the host. APT authenticates source and original package downloads. Third-party Qt builds, foreign-architecture Qt, other Qt upstream versions, and unavailable exact distro sources receive an explicit unsupported result. No guessed binary compatibility or automatic source substitution is permitted.

The new `tools/system-build.py` owns discovery, local build selection, native verification, and the command entry points. `tools/system_install.py` owns preparation of the separate activation package, deployment verification, and native package application/rollback. `packaging/` owns the optional backend capability patches and session scripts. Versioned patches own the Qt 6.8.2 port. Existing Qt 6.10.2 patches and rendering algorithms remain opaque supporting behavior. The Gui-to-Quick capability boundary composes normal official update handling. CMake and existing independent probes compose version compatibility and installed-runtime validation. Distro APT/dpkg semantics and complete Plasma startup remain native supporting owners exercised through real entry points.

The behavior floor is a matched installable package set for the detected source revisions, isolated compilation, complete source/provenance, disabled activation, explicit per-user enable/disable, verified official rollback, and preserved update ordering. The ceiling excludes a hosted repository, release signing, automatic package installation during a build, permanent loader overrides, manual library copies, font replacement, automatic blend policy, other toolkits, other APIs, concurrent builds, interrupted-build recovery, and arbitrary distro/version support. The existing private preview remains available unchanged.

## Smallest implementation


Expose `plan`, `build`, `prepare`, `verify`, `install`, and `rollback` through one Python entry point. `plan` reads `/etc/os-release`, native architecture, and the complete installed binary/source identities for QtBase and Qt Declarative. Save its JSON before `build`. Require both native runtime modules and one coherent official source revision per family. Record architecture-independent documentation separately and leave it unchanged. When rebuilding an already installed Fontreal set, use its packaged original-system record to identify exact official sources and rollback packages. Reject a mixed unsupported pair rather than infer its origin.

`build` uses the selected release's official container image, enables that image's matching source repositories, and retrieves exact source revisions. Preserve distro patch queues, append the matching Fontreal patch with strict application, and use distro `debian/rules` through `dpkg-buildpackage`. Build QtBase first and install its matching development packages only inside the container before building Declarative. Limit default parallelism and omit debug packages. Keep distro hardening and dependency rules. Record any build options. No host package or APT configuration changes occur.

The user's storage instruction places this workspace's generated build data on `/storage`. Preserve the familiar workspace paths with links to the external storage. Bind container `/tmp` to a directory under the selected build or package-check output. Keep compiler objects, source staging, package artifacts, captures, logs and test VM disks on that storage. Disable duplicate persistent container console logs. Preserve stored data and verify copies before removing their old files.

Apply a small package capability patch after each renderer patch. Export one versioned C predicate, `qt_fontrealFontV1(QFontEngine *)`, from the Gui FreeType owner. It delegates to the existing eligibility method. Quick references it as an optional ELF weak symbol. Quick's existing global gate requires both the opt-in environment and this actual loaded capability. Its font helper calls the predicate only behind that gate. Remove the direct Quick relocation to the Fontreal-only C++ method and its FreeType engine header. This also removes the need for FreeType compiler flags in the Declarative package. Keep the original private preview payloads unchanged. Include both renderer and capability patch hashes in the system plan and corresponding source.

The global gate precedes surface requests, native per-run selection, glyph-origin treatment, color conversion, marked target creation, pipeline flags, and private write-view member access. Official Gui with candidate Quick must load under immediate symbol binding and render stock output, even with enabled values inherited from the old session. Candidate Gui with official Quick must remain usable. Do not force exact package-pair dependencies to avoid either transition. Session version checks remain separate and deactivate the next unsupported login.

Download every original native package selected for replacement before compilation. Keep the originals with hashes for offline rollback. Emit architecture-specific binaries and both modified source packages, their original archives, notices, `.buildinfo` and `.changes` files, dependency inventory, exact patch hashes, Git identity, image identity, build options, and test results. Finalize `bundle.json` only after checking the complete set and its hashes. Empty output or a missing later-module artifact cannot become a successful bundle. Source archives must unpack with the Fontreal patch queue intact.

Append `afontreal` and a numeric build identity to the appropriate official revision. Compare the result with its base and the normal Debian/Ubuntu security, binNMU and next-revision forms using `dpkg --compare-versions`. The letter prefix avoids the `+fontreal` suffix that sorts above Ubuntu's `ubuntu` security suffix. Do not add holds or APT priorities. Record the base independently from the downstream revision, including original per-binary binNMU identities.

`prepare` consumes a complete verified native bundle without changing its `bundle.json` or native payloads. Build only the small disabled session package. Retain `activation/fontreal-session.deb`, both session scripts, the notice, and the exact package recipe. Write a separate `deployment.json` that binds the native manifest hash and the complete activation artifact hashes. Refuse existing activation output. Verify the package identity, saved system record, both exact runtime-version lines, and packaged payload against its retained source. Do not recompile Qt to change activation packaging.

`install` verifies both manifests, distribution, architecture, source pair, complete installed package membership, and current versions before invoking APT. Require successful package/update and complete runtime/recovery reports bound to both manifest hashes. Package-only evidence without both independent update cases is insufficient. Offer simulation with the same package list. Select the rebuilt counterpart for every replaced native package, plus the activation package. Stop on any proposed removal. Keep installation separate from build and require completed applicable validation before host deployment. Use ordinary package ownership and normal library paths. No automatic desktop restart occurs.

The separate `fontreal-session` package provides a Plasma environment script, a small per-user enable/disable command, and the original-system record. Installation leaves user activation absent. Enabling creates only the user's Fontreal marker. At the next session startup, export rendering=0 and empty blend/contrast values by default. Export rendering=1, blend=linear, contrast=mild only when the marker and both exact patched runtime versions match. KDE's source-script and service-environment import paths update present keys without removing absent keys. Explicit inactive values replace a retained enabled environment when the user manager survives logout. Do not force a Qt Quick renderer or change fonts. An official update makes the matching-pair condition false. Disable removes the marker. Full rollback uses the saved official packages for the complete replacement set and removes the activation package through APT. Both routes must work from a console.

## Decision Log


Use native distro packaging in a clean container rather than deploy the partial upstream runtime or copy libraries. This preserves dependency and package ownership while keeping host build dependencies untouched. On-demand source selection fixes the upstream version from the running system, not from the newest release. Matching patch ports are explicit. Unknown versions stop.

Use the existing Qt mechanism for 6.8.2. Official source inspection shows bounded source-context differences and the required native APIs. Porting still requires compilation and independent pixel proof. No new rendering algorithm is selected, so arXiv architecture research adds no decision evidence here.

Separate current build inputs from retained artifact verification. A new build requires hashes for the checkout's actual patches. A retained bundle verifies against its own hashed source and original packages, so a later checkout change cannot prevent official rollback. The direct CLI check contrasts a stale plan rejected for building with the same retained bundle accepted for verification.

Source retrieval, package building, version comparison and container boundaries follow official APT, dpkg and Docker documentation. See [deployment research](../research/distribution.md). Hosted repository signing and the public project license remain FR-012. Local corresponding source and notices remain required now.

The private prototype requires a matching pair and has a strong Quick dependency on a Fontreal-only Gui method. That is outside FR-013's unmatched-pair model. FR-011 promotes independently maintained official updates and must remove that deployment dependency before delivering packages. An optional versioned C predicate preserves the actual Gui eligibility owner and gates every Quick-specific action. It avoids a duplicate font policy, dynamic loading of a second Gui library, and package locks. GNU ELF weak references supply the native mechanism. This is standard loader integration, not a new rendering algorithm. See [GCC weak references](https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html#index-weakref-function-attribute). Scope: unfinished P1/P2 capability and update proof. Existing rendering behavior and the private preview remain unchanged.

Refine the unfinished P2 inactive encoding to explicit rendering=0 and empty blend/contrast values. This supersedes only the unset-only starting mechanism, not its stock-rendering result. Plasma 6.3.5 [sourceFiles](https://raw.githubusercontent.com/KDE/plasma-workspace/v6.3.5/startkde/startplasma.cpp) imports keys from the sourced environment and does not remove missing parent keys. Its systemd import also restores retained non-session keys. Test enabled → disabled and official-update → fallback while the user manager remains alive. The marker remains the preference owner, and the session hook remains the only package writer of these startup values.

Keep native compilation and activation preparation separate. One manifest describes the immutable native build. Another binds the independently prepared session package to that build. This avoids native recompilation and a validation hash cycle. Both report bindings are required for deployment. A supported on-demand rebuild can start with earlier Fontreal packages installed. Its guarded apply proof must restore that actual predecessor, not the distinct official rollback baseline. These refinements apply only to unfinished P2 under the existing B1/B4/B5 boundaries.

Use normal APT acquisition of the selected local `.deb` files. Do not pass `--no-download`. That option restricts APT to its download cache and can reject local Fontreal archives that need file acquisition. See the [APT option definition](https://manpages.debian.org/trixie/apt/apt-get.8.en.html). Prove offline rollback by running the real command inside a disposable test [network namespace](https://manpages.debian.org/trixie/util-linux/unshare.1.en.html) without network connectivity. Keep the installer, APT, exact cached artifacts, version checks, and removal gate real. This refines only the unfinished P2 transport and test mechanism. It adds no persistent APT configuration or new recovery policy.
