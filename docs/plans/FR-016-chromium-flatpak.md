[Capability sets](https://man7.org/linux/man-pages/man7/capabilities.7.html), [NoNewPrivs](https://docs.kernel.org/userspace-api/no_new_privs.html).

Every named check reaches the real production owners and final application observation. Component tests support those sequences and cannot replace them. Keep descriptor lifetime, application-view selection, retained hooks, normal reopening, official updates and reversal in the same causal lifecycle until the final stock observation. Full FR-016 review and completion remain separate from a clean C2 checkpoint.

Bitwarden's own engine, disabled RunAsNode fuse and isolation preload require independent qualification. Do not fix or drop that security chain as part of a font override. Edge's closed-source installed product has no established native glyph hook; do not replace its browser or migrate its profile to claim support. Telegram's installed build includes Pango/Cairo custom text and separate static Qt controls. Existing effective grayscale/full-hint/metric options can supply the Pango geometry without a mandatory application patch. Their precedence, reached raster, caches and final composition still need proof. A loaded runtime FreeType library establishes neither backend coverage nor complete Telegram support.

## Decision Log


The first implementation follows the exact Teams engine before changing application launchers. This makes the actual raster and compositor observable without using an account-bearing application as a test harness. Keep Bitwarden, Edge and Telegram in the inventory with their own evidence gaps. Preserve their launch chains until the relevant owner is proven.

The generic selected processor remains opaque in C1. This prevents an engine investigation from reopening accepted optical tuning. Later ports must use independent raw inputs from their actual backend and preserve the selected generic processing semantics.

Scope: unfinished C2 only. C2 uses Fontations rather than changing font factories. The unfinished C2 implementation preserves the native hinting-reliant branch: pinned Skrifa `outline/mod.rs` requires `Engine::Interpreter` and `Target::Mono` when `require_interpreter` is true, and the pristine Fontations scaler takes that branch even for normal/A8 requests. The earlier uniform-smooth interpretation was broader than the native provider contract. The pristine normal/A8 API versus independently requested FFI Mono check must establish this equivalence before selected comparisons; no cross-backend FreeType byte equivalence is claimed. Ordinary eligible outlines retain ForceOff/interpreter smooth-normal. The proposed requirement to select ordinary outlines inside color typefaces is rejected because the accepted native gate excludes the entire `FT_HAS_COLOR` face. The mixed-face regression remains required to prove that this original exclusion preserves all earlier rendering parameters. Grayscale EBDT is distinguished from color tables before eligibility.
